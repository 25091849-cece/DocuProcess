# Person 2 Database - Implementation Guide

## Overview

This guide provides technical implementation details for the DynamoDB database component of DocuProcess.

## Architecture Decisions

### Why DynamoDB?

1. **Serverless** - No infrastructure to manage
2. **Scalable** - Auto-scales with demand
3. **Cost-effective** - Pay-per-request model
4. **Performance** - Single-digit millisecond latency
5. **Integration** - Works seamlessly with Lambda and EC2

## Table Design Strategy

### Primary Key Selection

**Chose: `document_id` as Partition Key**
- UUID generated by Person 1's Lambda
- Unique identifier for each document
- Distributes evenly across partitions
- Supports fast lookups by ID

**Alternative considered**: Composite key with vendor+date
- Rejected: Not as flexible for queries
- Violates single responsibility

### Attribute Design

**Required Fields** (enforced in code):
- `document_id` - Unique identifier
- `vendor` - Company/vendor name
- `date` - Document date
- `amount` - Document amount
- `status` - APPROVED or NEED_REVIEW

**Optional Fields**:
- `confidence_score` - Extracted by Person 1
- `s3_location` - Location in S3
- `raw_text` - Full extracted text
- `last_updated` - Timestamp of last update
- Custom fields as needed

**Timestamp Handling**:
- Always store ISO 8601 format (YYYY-MM-DDTHH:MM:SSZ)
- Automatic `timestamp` on insert
- Automatic `last_updated` on modification

## Index Strategy

### Global Secondary Index (GSI)

**Index Name**: `status-timestamp-index`
- **Partition Key**: `status`
- **Sort Key**: `timestamp`
- **Projection**: ALL

**Benefits**:
- Fast query by status: `O(1)` vs `O(n)` scan
- Time-series ordering within status
- Supports Person 3's web app filtering
- Enables Person 4's notification queries

**Create via AWS CLI**:
```bash
aws dynamodb update-table \
  --table-name DocumentRecords \
  --attribute-definitions AttributeName=status,AttributeType=S \
  --global-secondary-indexes IndexName=status-timestamp-index,...
```

## CRUD Operations Implementation

### CREATE: Insert Single Document

```python
def insert_document(self, document: Dict[str, Any]):
    # Validation
    validate_required_fields(document)
    
    # Add timestamp
    document['timestamp'] = datetime.now().isoformat()
    
    # Insert
    self.table.put_item(Item=document)
    
    # Return success
```

**Key Points**:
- Validates all required fields present
- Auto-adds timestamp if missing
- Overwrites if document_id exists (use caution)

### CREATE: Batch Insert

```python
def insert_multiple_documents(self, documents):
    with self.table.batch_writer(batch_size=25) as batch:
        for doc in documents:
            batch.put_item(Item=doc)
```

**Key Points**:
- DynamoDB batch limit: 25 items per batch
- Automatic handling of pagination
- Efficient for bulk operations from Person 1

### READ: Get Single Document

```python
def get_document(self, document_id):
    response = self.table.get_item(Key={'document_id': document_id})
    if 'Item' in response:
        return response['Item']
    else:
        raise DocumentNotFoundError(document_id)
```

**Performance**: O(1) - direct lookup

### READ: Query by Status

```python
def get_documents_by_status(self, status):
    response = self.table.scan(
        FilterExpression='#s = :status',
        ExpressionAttributeNames={'#s': 'status'},
        ExpressionAttributeValues={':status': status}
    )
```

**Note**: Uses FilterExpression (expensive). With GSI:
```python
response = self.table.query(
    IndexName='status-timestamp-index',
    KeyConditionExpression='#s = :status'
)
```

### UPDATE: Modify Specific Fields

```python
def update_document(self, document_id, updates):
    # Build UpdateExpression dynamically
    update_parts = [f"{key} = :{key}" for key in updates]
    
    response = self.table.update_item(
        Key={'document_id': document_id},
        UpdateExpression="SET " + ", ".join(update_parts),
        ExpressionAttributeValues={f":{k}": v for k, v in updates.items()},
        ReturnValues='ALL_NEW'
    )
```

**Key Points**:
- Never overwrites entire item (use PUT for that)
- Returns updated item (ALL_NEW)
- Auto-adds last_updated timestamp

### DELETE: Remove Document

```python
def delete_document(self, document_id):
    self.table.delete_item(Key={'document_id': document_id})
```

**Performance**: O(1)

## Search Functionality

### Client-Side Filtering Strategy

```python
def search_documents_by_vendor(self, keyword):
    # Scan all documents
    response = self.table.scan()
    items = response['Items']
    
    # Client-side filter
    results = [item for item in items 
               if keyword.lower() in item['vendor'].lower()]
    
    return results
```

**Trade-offs**:
- Pro: Flexible, case-insensitive, partial matching
- Con: Slower for large datasets

**Optimization for production**:
- Create separate search table with full-text index
- Use Elasticsearch for advanced search
- Denormalize commonly searched fields

### Date Range Search

```python
def search_documents_by_date(self, start_date, end_date):
    # Scan and filter
    items = self.table.scan()['Items']
    
    results = [item for item in items
               if start_date <= item['date'] <= end_date]
    
    return results
```

**Alternative** (if needed):
- Create GSI with date as partition key
- Query by date range directly

## Pagination Handling

```python
def retrieve_all_documents(self):
    items = []
    response = self.table.scan()
    
    items.extend(response.get('Items', []))
    
    # Handle pagination
    while 'LastEvaluatedKey' in response:
        response = self.table.scan(
            ExclusiveStartKey=response['LastEvaluatedKey']
        )
        items.extend(response.get('Items', []))
    
    return items
```

**Key Points**:
- DynamoDB returns max 1 MB per request
- Use LastEvaluatedKey for next page
- Automatic in boto3 resource API

## Performance Optimization

### Query Performance Tips

1. **Use Keys not Filters**
   - Query vs Scan: Query is 10x faster
   - Use GSI for filtered queries

2. **Batch Operations**
   - Batch write: ~25 items per request
   - Reduces round trips to DynamoDB

3. **Projection**
   - Only retrieve needed attributes
   - Reduces data transfer

4. **Limit Results**
   - Use Limit parameter for pagination
   - Avoid full table scans

### Example: Optimized Query

```python
# Inefficient: Scan entire table
response = self.table.scan(
    FilterExpression='#s = :status'
)

# Efficient: Query with GSI
response = self.table.query(
    IndexName='status-timestamp-index',
    KeyConditionExpression='#s = :status',
    Limit=100,
    ProjectionExpression='document_id,vendor,status'
)
```

## Data Consistency

### Strong vs Eventual Consistency

**DocuProcess Uses**: Eventual consistency (default)
- Acceptable for document review workflow
- Lower cost and latency
- Documents propagate within milliseconds

**When to use Strong Consistency**:
- Financial transactions (not applicable here)
- Cross-region consistency critical (not needed)

```python
response = self.table.get_item(
    Key={'document_id': 'DOC-001'},
    ConsistentRead=True  # Force strong consistency
)
```

## Backup & Recovery Strategy

### Automated Backups

- Point-in-time recovery (PITR): 35-day window
- Automatic snapshots: No action needed
- Zero impact on performance

### Manual Backups

```bash
aws dynamodb create-backup \
  --table-name DocumentRecords \
  --backup-name DocumentRecords-$(date +%s)
```

### Restore Procedure

```bash
aws dynamodb restore-table-from-backup \
  --target-table-name DocumentRecords-restored \
  --backup-arn <backup-arn>
```

## Production Considerations

### Scaling Strategy

1. **Capacity Planning**
   - Estimate read/write volume
   - Start small, monitor metrics
   - Scale based on actual usage

2. **Cost Optimization**
   - Use provisioned capacity for predictable load
   - Use on-demand for variable load
   - Monitor and adjust regularly

3. **Security**
   - Enable encryption at rest
   - Use VPC endpoints
   - Implement fine-grained IAM policies
   - Enable CloudTrail for audit

4. **High Availability**
   - Multi-AZ (automatic)
   - Global Tables for disaster recovery
   - Backup to another region
